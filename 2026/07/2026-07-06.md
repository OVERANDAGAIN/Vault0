## 1. 新增的 user 类型

新增文件：

```text
src/recdiag/core/simulators/llm_driven_simulator.py
```

新增类：

```python
LLMDrivenUserSimulator
```

它和当前的 `ProfileSimulator` 是并列关系，不替换原来的类。

核心区别是：

```text
ProfileSimulator:
  profile + SimulatorState + AdReactionModel + response_generator

LLMDrivenUserSimulator:
  initial profile + dialogue history + latest assistant utterance
  -> LLM directly decides next user response and ad outcome
```

也就是说，新 user 不调用：

```python
AdReactionModel
```

广告是否接受、是否拒绝、是否点击、是否厌烦、是否结束任务，全部由 user LLM 在结构化 JSON 中输出。

---

## 2. 新 user 的输入

每轮输入给 user LLM 的信息主要是：

```text
1. 静态 user profile
2. episode-level sim_params
3. 当前可观察对话历史 history
4. latest assistant message 是否是广告
5. latest assistant metadata 中的少量事实字段
```

其中第 4、5 点只是告诉 LLM 当前 assistant message 是不是广告，以及广告类别、品牌、相关性等事实信息。它不是 rule feedback，也不是 reaction model。

---

## 3. LLM user 输出格式

新 user 要求 LLM 返回 JSON：

```json
{
  "text": "the user's next message",
  "read_ad": false,
  "ad_outcome": "accepted | clicked | ignored | rejected | none",
  "task_completed": false,
  "exit_reason": null,
  "satisfaction": 0.0,
  "patience": 0.0,
  "intent": "continue | ask_followup | switch_topic | exit"
}
```

然后代码会把它转成现有系统需要的：

```python
UserResponse(
    text=...,
    read_ad=...,
    metadata={
        "ad_outcome": ...,
        "satisfaction": ...,
        "patience": ...,
        "task_completed": ...,
        "exit_reason": ...,
        ...
    }
)
```

这样 `DialogueEnv`、`Monitor`、`RewardCalculator`、`MetricsCalculator` 基本不用重构。

## 6. 这次修改的关键点

这次不是把 `ProfileSimulator` 改成 LLM，而是新增了一个并列 user：

```text
ProfileSimulator        # 原有 rule/reaction-model user
LLMDrivenUserSimulator  # 新增 fully LLM-driven user
```

因此后续实验可以形成清楚对照：

| user simulator       | 广告反馈来源            | 普通回复来源        | 用途                    |
| -------------------- | ----------------- | ------------- | --------------------- |
| `profile` + `corpus` | `AdReactionModel` | corpus        | 低成本规则基线               |
| `profile` + `llm`    | `AdReactionModel` | LLM generator | 半 LLM user            |
| `llm`                | LLM               | LLM           | 真正 LLM user simulator |

下一步应该重点比较：

```text
profile + llm response
vs
llm-driven user
```

看广告接受率、拒绝原因、task completion、自然结束质量是否发生系统性变化。
