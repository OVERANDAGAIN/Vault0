## SalesBench 上轮会议要点

### 1. 先以 Market-Bench 为参照，确认基础机制

会议先围绕 Market-Bench 的实现进行了拆解：

* 多个 Seller 同处一个市场，但不直接交流，主要通过公开的价格、slogan、销量等信息观察竞争者。
* 所有 Seller 面对相同的商品基础进货价，但实际采购成本由竞拍决定。
* Agent 每轮会获得资金、库存、供应信息、历史市场反馈等状态，再输出采购、定价和 slogan；本身不是典型的主动 tool-use Agent。
* Seller 可以通过别人公开的价格、slogan 和销售结果间接学习竞争策略。

这部分主要是为了确定：**已有 benchmark 已经做到哪里，我们还有什么空间。**

### 2. 讨论 SalesBench 的核心卖点

可能的方向包括：

* **更贴近真实商业环境**：不只做简单的定价和购买规则，而是更接近真实电商/销售过程。
* **多 Seller 竞争**：除了价格竞争，还可以出现商品竞争、话术模仿、竞品比较甚至语言层面的竞争。
* **高质量 User Mock / Consumer Environment**：如果能提供统一、可测试、可复现的消费者环境，本身也可能成为重要贡献。
* Agent 可以进一步具有主动工具调用能力，而不是每轮被动填写固定动作。

其中一个核心问题是：**“real-world aligned”到底如何证明，而不是仅靠设计看起来真实。**

### 3. 评价问题：利润客观，但消费者模拟仍然决定可信度

SalesBench 相比普通对话 benchmark 的优势，是可以直接用：

* 销售额；
* 利润；
* 库存；
* 成交等

作为客观结果，不一定依赖 LLM Judge。

但如果 Buyer 是模拟的，就会出现新的问题：

> 即使最终指标是利润，利润仍然是由 User Simulator 的购买行为产生的。

因此 **User Mock 的真实性和验证方式** 会成为整个 benchmark 是否可信的关键。

### 4. 真人用户可能作为重要验证手段

会议进一步讨论了真人实验的可能性：

* 初期可以从朋友、微信、高校人群等做小规模测试；
* 如果可行，再考虑企业合作或更大范围推广；
* 真人购买能够给 User Mock 和 benchmark 提供更强的现实依据。

但真人实验也带来：

* 招募成本；
* 用户分布偏差；
* 实验不可完全复现；
* 运营和长期维护成本。

因此目前更像是考虑：

> **模拟环境作为主要 benchmark，真人实验作为真实性验证或补充。**

### 5. 如果做真人交易，商品本身也是设计问题

实体商品虽然真实，但存在采购、库存、物流、地域和履约成本。

因此会上讨论了一些更容易实验的商品形式：

* 数字产品；
* API / 模型 Token 等数字额度；
* 充值、打赏或会员权益；
* 平台优惠券；
* 课程/知识产品；
* 农产品等实体商品作为其他可能性。

理想商品需要同时满足：

> **有真实价值、用户愿意购买、成本可控、容易交付、实验可扩展。**
