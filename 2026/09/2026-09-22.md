# 消费者模型

```
你负责 SalesBench 的“用户模拟方法与可复用资源调研、选型”。

我们希望构建具有个体差异、消费习惯和持续状态的 Mock User。他们会对商品、商家、销售互动以及可见的其他用户行为产生反应，可能浏览、交流、比较、购买或离开，过去经历也可能影响之后的行为。

本轮请从已有研究和实现出发，调查别人怎样设计用户，哪些方案或组件可以直接使用、改造或组合；只有现有资源确实不适合时，再考虑寻找数据训练。不要先自行规定一套用户属性、心理分数和更新公式，再寻找支持材料。

**一、调研范围**

在已有 W2 调研基础上，检查并适当扩展到：

* 推荐系统中的用户模型与交互模拟器；
* 对话推荐、购物与销售中的用户模拟；
* 消费行为、市场与社会仿真中的个体或群体模型；
* 从真实行为数据学习用户反应的方法。

同时关注规则、统计或学习模型、LLM，以及混合方案，不预设某一路线最好。

区分“帮助用户完成任务的 Agent”和“模拟用户自身偏好与行为的模型”。前者只有在机制确实可借用时才纳入。

优先考虑有可靠发表记录、充分实验、公开实现或实际应用依据的工作；有价值的预印本也可纳入，注明状态。机构和发表级别作为参考，不能替代对机制、证据和资源的检查。

**二、先把每项相关工作讲清楚**

对重点工作，先用通俗语言说明：
它研究什么问题，用户在什么环境中活动，接收什么信息，内部怎样表示用户，最终产生什么行为。

然后再介绍技术实现和与我们的关系。至少用一个小例子解释“输入什么，模型怎样处理，输出什么”，避免只罗列术语和结论。

重点查看论文正文、附录、官方代码、模型和数据说明。明确区分论文声称支持、代码实际实现和你的推断。

**三、用固定维度横向比较**

至少比较以下方面：

1. 人群差异：是否生成或拟合用户分布，属性之间是否有关联，依据来自哪里。
2. 个体表示：偏好、消费能力、习惯、需求等如何表示和获得。
3. 动态状态：是否考虑满意度、信任、情绪、记忆或需求变化；怎样更新，是否经过验证。
4. 反应对象：能对商品、商家、自然语言、其他用户或群体信息中的哪些内容作出反应。
5. 行为范围：输出喜欢与否、评分、点击、对话、购买、退出，还是持续多轮行为。
6. 实现机制：规则、学习模型、LLM 或混合；各自负责哪一部分。
7. 验证依据：使用了什么真实数据、人工评价、行为预测或其他检查，究竟验证了什么。
8. 可复用程度：代码、权重、数据、运行条件、许可证和适配工作量。

不是每篇都需要具备全部能力。请标明“已支持、部分支持、未涉及、信息不足”，并简要说明依据，避免把未披露写成没有实现。

收入、习惯、满意度等只是关注点，不要求每个属性都单独数值化。若已有研究采用其他有效表示，应解释其意义。

**四、核查哪些东西真正能拿来用**

对最值得考虑的候选，实际检查可获得的资源，而不只贴论文链接：

* 能直接调用的模型或完整模拟器；
* 可以复用的用户生成、偏好建模、记忆或状态更新模块；
* 可以复用的行为数据、训练方式和评测工具；
* 只有设计参考价值、暂时无法运行的工作。

说明接入我们多商家、公开交流与私信、持续消费场景时，哪些可以保持，哪些必须修改。

不强求找到一篇包办所有需求的论文，也不默认必须拼接多个系统。若建议组合，说明它们的用户定义、状态和行为输出是否兼容，以及组合会引入哪些额外假设。

对首选方案，条件允许时运行官方最小示例，或检查实际输入输出。未运行就明确标注，不要另写一个自有演示来代替对原方案的验证。

**五、最后再判断是否需要训练**

只有在明确现有方案的具体不足后，再讨论训练：

* 缺的是人群分布、偏好预测、对话反应、购买选择，还是长期状态变化；
* 有哪些可获得数据，记录了什么行为，能提供什么标签；
* 数据与我们场景有哪些差异，哪些能力无法从这些数据中学到；
* 能否先复用现有模型或调整表示，训练预计解决什么问题；
* 怎样与不训练的方案比较，避免仅凭几个看起来合理的例子判断有效。

如果训练条件尚不具备，给出有依据的阶段性选型，不要用随意设定的参数冒充数据驱动的消费者模型。

**六、交付要求**

输出一份主报告，开头先回答：

* 目前最值得我们采用或改造的方案是什么；
* 可以直接复用哪些资源；
* 还缺什么，是否需要训练；
* 下一步最值得执行的一个验证是什么。

后面包含重点工作的清楚介绍、统一比较表、资源核查结果和推荐理由。详细来源放在对应结论附近。

已有 W2 的结论可以沿用，但需要检查是否适用于本轮更完整的 Mock User 目标。不要为了证明我们的创新而预设“现有工作都不够”，也不要把报告写成一串要求我自己回答的问题。

UI 和平台工程由其他 Work 负责。本轮先完成用户模拟的依据与选型，暂不自行设计完整市场环境，也不要求立即训练或实现最终消费者系统。

```
