# 3. 第一版 SalesBench 应该长什么样

### 一个 Sales Agent，在 3 天内面对一批潜在消费者，如何最大化最终利润？

每一天，它都可以：

| 类别          | Agent 决策         |
| ----------- | ---------------- |
| Targeting   | 今天联系哪个用户         |
| Product     | 给这个用户推荐哪个商品      |
| Dialogue    | 怎么跟他交流           |
| Pricing     | 最终开什么价格          |
| Timing      | 现在继续聊、成交，还是以后再联系 |
| Information | 从对话中收集什么用户信息     |

消费者不是单次生成的 NPC，而是**persistent user**。

例如用户 \(u_i\) 有：

$$
z_i =
(\text{budget},
\text{preference},
\text{price sensitivity},
\text{impulsiveness},
\text{patience},
\text{satisfaction},
\text{purchase history}, ...)
$$

其中一部分是固定属性，一部分是动态属性。

比如：

**固定/慢变量**

收入层级、消费倾向、品类兴趣、价格敏感程度、冲动消费程度。

**动态变量**

剩余预算、心情、满意度、对商家的信任、过去购买、最近是否已经消费。

这样同一个人：

> Day 1 不买
> Day 2 看见别人买了
> Day 3 有优惠 + 对 seller 信任提高
> → 买了

这就开始有你们想要的 **dynamics** 了。

# 4. “Mock user”这部分，我认为会议里有一个特别重要的认识

记录里这句话非常关键：

> **关注整体的群体分布，而不是一个人单次对话里体现。**

这比“我要做一个特别逼真的 Persona Prompt”重要得多。

你们真正需要验证的不是：

> 这个 Mock User 像不像某一个真人？

而是：

> 跑 1000 个用户以后，它们整体的消费行为分布是否合理？

例如：

| Population statistic | 希望控制什么          |
| -------------------- | --------------- |
| 收入 / 可支配预算           | 有穷有富，而不是所有用户差不多 |
| 消费倾向                 | 有计划型，也有冲动型      |
| 价格敏感性                | 对折扣反应不同         |
| 品类兴趣                 | 消费偏好异质          |
| 购买频率                 | 高频 / 低频         |
| 品牌/商家忠诚              | 会形成历史效应         |
| 社会影响程度               | 有些人跟风，有些人独立     |
| 情绪/满意度               | 销售行为影响未来购买      |

所以 Mock 的研究问题应该从：

**“LLM 能不能扮演一个消费者？”**

提升成：

**“如何构造一个统计意义上合理的 synthetic consumer population？”**

这会成为 SalesBench 很重要的一块。

# 5. 关于“收入”和 Budget，我建议稍微区分

会议记录里现在有：

> 收入阶层
> 月收入
> budget 上限

这三个不要等同。

比较合理的是：

$$
Income_i \rightarrow Budget_{i,t} \rightarrow WTP_{i,p,t}
$$

也就是：

**收入**决定长期消费能力范围。

**Budget**表示当前周期里还能消费多少钱。

**WTP（Willingness To Pay）**表示这个用户对某个具体商品愿意支付多少钱。

比如：

一个月收入 20k 的人，不代表愿意花 3000 买耳机。

但他可能：

> monthly income = 20k
> discretionary budget = 4k
> headphone WTP = 800
> course WTP = 2000

这样销售和定价才有真正的决策难度。

而现有 PrefBench 已经证明一个很有意思的问题：LLM seller 即使几乎总能把交易谈成，也不意味着它**定价定得好**，有些简单启发式策略的利润反而明显更高。([arXiv][2])

这和你们会议里的“sales 不只是对话，而是选择和定价”高度一致。

# 6. Q1：“Sales 能看到用户多少信息？”其实是核心研究问题

会议里：

> 是否可以看到用户的一些信息，比如轨迹 or 整体画像

这个问题不要简单选择“能”或者“不能”。

我建议做成 **Partial Observability**。

也就是用户真实状态是：

$$
S_{user}
$$

Sales Agent 只能观察到：

$$
O_{seller} \subset S_{user}
$$

例如：

### Seller 可以看到

用户公开 profile、过去和**自己**的聊天记录、自己店铺的购买记录、公开点赞/浏览行为、市场总体统计。

### Seller 看不到

真实 WTP、真实剩余 budget、“冲动型=0.73”这种 simulator latent variable、真实购买概率。

于是 Agent 必须从：

> 对话 + 历史行为 + 市场信号

来推断：

> **这个人到底想不想买、多少钱会买。**

这个设置非常重要。

否则如果直接告诉：

> User 17：WTP=¥782，购买概率=0.74

那 Sales Agent 就不需要销售智能了。

反过来，如果什么信息都不给，它又很容易退化成随机试探。

# 7. 商品池也不能只是背景，它应该构成决策环境

会议说：

> 固定一个真实的选品池
> a. 进货价
> b. 库存量

我认为至少应该有：

$$
Product_j =
(Cost_j, BasePrice_j, Inventory_{j,t}, Category_j, Attributes_j)
$$

然后 Agent 自己决定：

$$
Price_{i,j,t}
$$

这样 reward 就不应该只看销售额。

应该至少是：

$$
R_t =
Revenue_t
-
COGS_t
-
InteractionCost_t
$$

进一步才考虑：

$$
+\ FutureCustomerValue
+\ PopularityValue
-\ HoldingCost
$$

所以一个 Agent：

> ¥100 进货，¥101 卖出去 100 件

成交率很高，但实际上可能不是好 Sales。

这也是为什么**利润应该比 close rate 更接近主指标**。

# 8. “交互 Cost”其实也是一个很好的研究维度

你们会议里记的：

> 实体经济 一对一 —— 线上平台

我理解它背后想表达的是：

**销售渠道具有不同 marginal cost。**

比如：

$$
Cost(DM) > Cost(Broadcast)/N
$$

一个销售一天可能只能深入聊 20 个人。

主播却能：

> 一次直播 → 1000 个用户

但是 broadcast 的个性化程度降低。

于是未来就会自然产生一个特别有意思的问题：

> **Agent 应该把有限的高成本 1v1 沟通机会给谁？什么时候应该广播？**

这时候“LLM 调用成本”甚至都可以进入 benchmark：

$$
Profit =
SalesProfit
-
\lambda \times TokenCost
$$

同样赚 ¥10000：

Agent A 聊了 3000 轮；

Agent B 聊了 300 轮。

B 显然经营效率更高。

# 9. 群体效应是第二阶段真正有潜力的东西

当 Level 1 跑通以后，再加入你们会议中的：

> 排行榜
> 看别人消费记录
> 点赞
> 人气
> T+1
> 广播
> 直播

这时候：

$$
Purchase_{i,t}
$$

不仅影响这个消费者，而且改变：

$$
Popularity_{product,t+1}
$$

进而影响其他消费者：

$$
P(Purchase_{k,t+1})
$$

也就是：

$$
Action_t
\rightarrow MarketState_{t+1}
\rightarrow FutureReward
$$

这才是真正的 **long-horizon sales strategy**。

例如一个聪明的 Agent 可能发现：

> 今天对几个高影响力用户低价卖
> → 商品进入榜单
> → 明天自然购买增加
> → 后面恢复高价

这已经不是“会不会销售话术”了。

而是一个真正的**策略学习问题**。

这也解释了会议里最后提到的：

> 对话策略
> 群体效应
> 更高级的，计策等

我觉得这完全可以作为 SalesBench 的三个难度层级。

# 10. “水军”我建议先不要直接加

它确实属于高级策略：

> 人为制造 popularity → 改变其他用户购买行为。

但一旦加入，研究问题会突然扩张成：

**market manipulation / strategic deception / platform gaming。**

这不仅让 simulator 难很多，而且很容易把 benchmark 主线带偏。

更干净的第二阶段可以先只做：

> organic social proof

比如：

真实购买数量、真实排行榜、真实评论、真实点赞。

等这些机制跑通后，再研究：

> 是否允许付费 promotion / seeding / strategic influence。

现有 SalesBench 主要关注多天 pipeline 和 buyer 互动；PrefBench 则把隐藏偏好和利润敏感定价单独拿了出来。([Hamza Mostafa][1])

所以我现在会把你们潜在的 gap 描述成：

> **现有 benchmark 多数仍然把“销售”建模为对一个 buyer 的对话/谈判过程，而真实销售同时包含 customer selection、product selection、pricing、information acquisition 和有限资源分配，并且这些行为会通过库存、历史与社会信号改变未来市场。**

这个 gap 是值得接下来重点验证的。

# 13. 因此你们“调研阶段”现在真正该查的东西

不要围着关键词 `SalesBench` 一个劲搜论文。接下来应该拆成五条调研线：

1. **Sales / Negotiation Benchmarks**：已有 benchmark 到底把 action、state、reward 做到了哪一步，尤其 SalesBench、SalesLLM、PrefBench 等，防止重复造轮子。
2. **User Simulation**：怎样构造 heterogeneous consumer population，重点研究真实分布、WTP、budget、消费习惯和 longitudinal state，而不是单纯 Persona Prompt。
3. **Market / Recommender Simulation**：库存、动态需求、用户轨迹、曝光—点击—购买、social proof 等现成模拟框架怎么做。
4. **Live Commerce / Social Commerce**：直播销售、排行榜、群体购买、主播影响等有没有可以抽象成 benchmark mechanism 的经验研究。
5. **Environment Design**：重点横向比较 Observation、Action、Transition、Reward、Horizon、Cost 和 Evaluation，而不只是“用了什么模型”。

## 最后，我觉得这次会议之后最应该先锁死的是一个 **MVP Research Definition**

暂时不要定义成“模拟抖音”。

先定义：

> **100 个 persistent simulated consumers + 20~50 个商品 + 1 个 Sales Agent + 3 天。消费者具有异质 budget/preferences/WTP/history；Sales 只能部分观察用户状态，并决定联系谁、推荐什么、如何交流及如何定价。商品具有成本与库存。最终以累计利润为主指标，同时记录成交率、销售额、交互成本和用户满意度。**

先把这个东西和现有所有 benchmark 对一遍。

如果这个版本就已经存在，你们再改。

如果没有，那么**这就是现在最值得继续往下挖的核心原型**。

而“库存动态 → 群体效应 → 排行榜 → 一对多直播 → 多 seller 竞争”，可以非常自然地一层一层往上叠，而不是现在一次把整个抖音商城都模拟出来。

# 六、Simulator Fidelity 是独立研究问题

请专门建立一条调研线：

* real transaction data
* distribution matching
* aggregate statistics
* held-out behavior prediction
* test-retest reliability
* calibration
* intervention consistency
* A/B testing
* external validity

需要特别区分：

### Individual Fidelity

一个 synthetic user 是否像对应的真人。

### Population Fidelity

一大群 synthetic users 的总体行为分布是否像真实人群。

### Dynamic Fidelity

经过多轮交互以后，行为变化是否合理。

### Causal Fidelity

改变 price / ranking / social proof / advertisement 后，反应方向和幅度是否符合真实实验或已有经济学结论。

请调查这四种 fidelity 分别有没有已有 benchmark / metric / methodology。
