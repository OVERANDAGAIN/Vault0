# Batch 失败传播问题（暂不修改，后续复查）
当前 V1 候选语义是：同一 Actor 的 action batch 中，若某个 action 出现正常业务失败，则该 Actor 本 batch 后续 action 均标记为 skipped；不会导致其他 Actor、当前 Wave 或整个实验直接退出。
隐患在于：Runner 默认把“后续动作”视为依赖前一个动作成功，但实际上后续动作可能彼此独立。例如私聊失败不一定意味着改价也应取消。这样可能导致环境替 Agent 修改原本已经生成的策略。
V1 可暂时保留这一规则以降低实现复杂度，但必须记录失败与 skipped 原因。后续应比较：①失败即停止；②业务失败后继续执行；③Agent 显式声明 depends_on / on_failure。在正式 Benchmark 前决定，不应长期隐藏在执行代码中。
