## 二、完成一次真实的完整任务

尽量使用一个小但真实的 GPU 项目，不要只跑 Hello World。

测试项目最好包含：

* 一个已有代码工程；
* 至少一个子目录或额外文件；
* requirements / 环境依赖；
* 明确使用 GPU；
* 最终产生可以下载并检查的结果文件。

实际走完整流程：

**注册/登录 → 充值/实名/授权等门槛 → 创建或选择资源 → 工程进入 → 环境准备 → 启动任务 → 确认真正运行 → 查看状态和日志 → 获得结果 → 取回结果 → 停止资源。**

重点观察并记录：

### 开始使用

* 注册、充值、实名、授权分别是否需要；
* 这些门槛什么时候才出现。

### 项目接入

* 代码、数据、模型、素材到底怎么进去；
* 子目录和额外文件是否正常；
* 路径和外部依赖怎么处理；
* 原工程需要改多少；
* 提交前平台会不会检查缺文件、错误路径、入口、兼容性。

### GPU / 环境

* 用户选具体 GPU、选规格，还是只提需求；
* 没有资源时怎么办；
* 镜像和环境怎么准备；
* CUDA、驱动、框架版本谁负责；
* 缺依赖时平台做什么、用户做什么。

### 执行

* 怎么正式开始运行；
* 是否生成 Task / Job ID；
* 能看到哪些状态；
* 有没有日志；
* 能否证明真正执行了业务代码和目标 GPU，而不是只“分配到了 GPU”。

### 结果

* 输出是否自动成为平台里的结果；
* 保存在哪里；
* 怎么拿回本地；
* 是否需要自己拼接、打包或整理；
* 谁确认结果完整、可用。

### 停止

* 什么操作真正停止计算；
* Stop / Shutdown / Release / Delete 是否不同；
* 任务结束后是否还需要主动释放；
* 是否能看到最终费用或停止状态。

保存关键截图即可，不需要每一步截图。优先保留：

* 资源/任务配置；
* 实际运行和 GPU/日志证据；
* 任务状态；
* 结果；
* 停止资源与费用终态。

## 三、成功以后，再补测三个容易遗漏的问题

不要第一次成功就结束。

### 1. 再跑一次

用同一个项目重新运行一次，观察：

* 资源配置是否复用；
* 环境/镜像是否复用；
* 代码和数据是否重新上传；
* 参数是否保留；
* 已有结果能否复用；
* 第二次究竟还需要重复哪些人工操作。

可以顺手改一个参数或少量代码，看变化以后需要重新做多少准备。

### 2. 本地关闭以后

在一个运行中的任务上，选择适合该产品的一种方式测试：

* 关网页；
* 关 IDE；
* 关提交终端；
* 退出客户端。

确认：

* 已提交任务还是否继续；
* 只是当前步骤继续，还是整个流程继续；
* 是否仍需要本地客户端、控制服务或共享存储保持在线。

### 3. 做 1～2 个简单异常测试

只选择最有价值的，不要大量制造故障。

例如：

* 缺一个文件；
* 错一个路径；
* 缺一个依赖；
* 输入参数错误；
* 主动抛代码异常。

记录：

`在哪发现 → 提示是否清楚 → 谁处理 → 修复后需要重做多少`

注意：

* 查询失败 ≠ 执行失败；
* 下载失败 ≠ 需要重新计算；
* 正常补算缺失部分 ≠ 自动故障恢复。
