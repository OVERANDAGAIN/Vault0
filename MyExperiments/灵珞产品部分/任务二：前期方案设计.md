# Work 2： 外部GPU相关
收敛为 **6 个产品：3 个详细体验候选，3 个专项参考**。

| 产品及研究范围 | 用户的典型使用方式 | 对 ComputeAstra 的主要参考价值 | 本次安排 |
|---|---|---|---|
| **[Runpod Pods](https://docs.runpod.io/pods/overview)** | 选择 GPU、环境模板和存储，进入远端环境，上传或拉取项目后运行 | 看清远端交互式开发的便利，以及用户承担的环境、运行和文件管理工作 | **详细体验** |
| **[Hugging Face Jobs](https://huggingface.co/docs/hub/jobs-overview)** | 提交自己的脚本或命令，说明依赖、硬件和文件位置，由平台执行任务 | 最直接对照“本地已有项目 → 提交计算 → 查看状态 → 取得结果”的完整流程 | **详细体验** |
| **[Modal Functions](https://modal.com/docs/guide)** | 为已有代码增加平台执行入口，用 Python 声明环境、GPU 和存储 | 判断少量代码适配能换取哪些便利，以及配置如何随项目复用 | **详细体验** |
| **[Coiled Batch Jobs](https://docs.coiled.io/user_guide/batch.html)** | 连接自己的云账号，提交脚本，利用本地软件环境同步完成远端运行 | 重点参考环境自动准备、目录上传和结果下载，检视“无需写镜像”的支持边界 | 专项参考；Batch Jobs 当前标为实验功能 |
| **[Lightning AI Studios / Jobs](https://lightning.ai/docs/overview/batch-jobs/sdk)** | 先在远端 Studio 准备项目，再用该环境提交后台任务 | 参考“先交互式调通，再提交执行”的衔接，以及环境快照和产物保存 | 专项参考 |
| **[SkyPilot Managed Jobs](https://docs.skypilot.ai/en/latest/examples/managed-jobs.html)** | 在已接入的计算资源上，通过任务配置提交项目、准备命令和启动命令 | 参考任务配置、执行管理、故障恢复与资源释放；需计入个人或团队的资源接入工作 | 专项参考 |

**本次详细体验候选及建议顺序：**

| 顺序 | 候选 | 重点查看的实际流程 | 希望回答的问题 |
|---|---|---|---|
| **1** | **Hugging Face Jobs** | 任务入口、脚本与依赖配置、输入输出目录、GPU 与超时选择、状态日志、结果获取 | 普通用户提交一次已有项目，到底需要明确哪些信息？插件能省去哪些步骤？ |
| **2** | **Runpod Pods** | 创建环境、模板与存储选择、项目导入、进入终端运行、断开连接后的管理、文件取回与关闭资源 | 哪些任务需要交互式排查？改成提交任务后，用户获得什么，又失去什么？ |
| **3** | **Modal Functions** | 项目接入、环境和执行入口声明、文件存储、后台执行、任务管理与结果获取 | 需要增加多少平台配置或代码？配置成功后，重复执行是否更简单？ |

其中，**Hugging Face Jobs 是与当前方案最直接的流程对照，Runpod 是交互式路径对照，Modal 是程序接入方式对照**。另外三个产品只补充关键问题，暂不扩大为完整体验案例。

# Work 3： Blender相关

| 候选 | 研究定位 | 主要原因 |
|---|---|---|
| **GarageFarm** | 重点案例 | Blender 插件提交、桌面工具传输、网页管理和结果下载，流程最贴近原方案 |
| **Flamenco** | 重点案例 | Blender 内提交到自有集群，适合研究共享存储、分帧和补算的前提 |
| **RenderStreet** | 保留候选 | 有明确的 Blender 插件提交流程，但与 GarageFarm 的商业服务模式较接近 |
| **SheepIt** | 补充参照 | 社区电脑供给接近闲置机器场景，但目前找到的 Blender 提交插件属于第三方，支持情况尚未确认 |
