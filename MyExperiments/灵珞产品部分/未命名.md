## 第 7 页：核心发现

建议只讲四个结论。

### 发现一：行业大多仍以资源为中心

用户首先需要理解 GPU、镜像、CUDA、磁盘、网络和计费，之后才能开始自己的任务。

### 发现二：单点能力已经相对成熟

* 自动构建有人做；
* 队列和 Agent 有人做；
* 多云路由有人做；
* Serverless 和远程 Offload 有人做；
* 闲置设备供给市场也有人做。

真正缺少的是组合和产品化。

### 发现三：需求侧体验会反向决定供给侧商业模式

> 难用 → 用户首次运行失败 → 真实订单少 → 供给方收益低 → 节点退出 → 资源质量下降。

这是老板最关心的商业逻辑。

### 发现四：结果交付不能只等于“提供日志”

完整结果交付至少包括：

* 环境能运行；
* 任务有明确状态；
* 失败能解释或重试；
* 费用可预估；
* 结果文件自动保存；
* 用户不必依赖 SSH 和 SCP。

# 四、今晚真实体验只跑这一个标准任务

为了让不同平台可以比较，不要在每个平台跑不同东西。

统一任务目标：

> 在 GPU 环境中运行一个小型 PyTorch 任务，生成 `result.json`，并把文件下载回本机。

在平台提供的 PyTorch 环境里运行：

```python
import json
import pathlib
import time

import torch

started_at = time.time()

a = torch.randn((2048, 2048), device="cuda")
b = torch.randn((2048, 2048), device="cuda")

for _ in range(20):
    result_tensor = a @ b

torch.cuda.synchronize()

result = {
    "gpu": torch.cuda.get_device_name(0),
    "cuda": torch.version.cuda,
    "elapsed_seconds": round(time.time() - started_at, 3),
    "shape": list(result_tensor.shape),
}

pathlib.Path("result.json").write_text(
    json.dumps(result, ensure_ascii=False, indent=2),
    encoding="utf-8",
)

print(result)
```

这里不是为了比较 GPU 性能，而是为了比较完整流程：

> 找到算力 → 准备环境 → 运行代码 → 看见状态 → 产生结果文件 → 下载文件 → 停止计费。

| ----------------- | ------------------------- |

# 七、接下来的实际执行顺序

## 第一优先级：共绩算力，45～60 分钟

完成：

* 整理现有供给侧设备记录；
* 补充设备配置、上线时间、定价和状态；
* 截取 24 小时无任务证据；
* 尝试找到平台是否解释未匹配原因；
* 体验一次需求侧创建任务；
* 记录卡住的准确页面；
* 发一次客服询问并记录发送时间。

即使需求侧任务没跑通，也要保留完整失败路径。

---

## 第二优先级：Vast.ai，30～45 分钟

目标不是深入研究，而是跑一遍海外 Marketplace 的首次用户流程。

重点观察：

* Template 和 Machine 为什么分开；
* 筛选机器需要理解多少指标；
* 是否容易判断可靠性；
* SSH/Jupyter 准备是否构成门槛；
* 镜像下载等待是否清楚；
* 停止和删除分别怎么收费；
* 结果怎样拿回来。

超过 10 分钟卡在支付或验证时就停止，不要继续死磕。把“无法快速完成注册/支付”也记录下来。

---

## 第三优先级：RunPod、SkyPilot、ClearML、Docker Offload

今晚只做官方文档级研究，不做完整安装。

你只需要能讲清：

* RunPod 如何从具体机器走向 Endpoint 和 API Result；
* SkyPilot 如何做 Managed Job 与恢复；
* ClearML 如何让 Agent 从队列拉任务并重建环境；
* Docker Offload 如何保留本地命令体验，却把执行放到云端。

这部分 AI 完全可以承担。

# 八、明天汇报的合格与优秀标准

## 合格

* 至少一个直接竞品有真实操作记录；
* 至少一条任务流程跑通或明确记录失败位置；
* 有行业三层分类；
* 有一张横向矩阵；
* 能回答“为什么他们难用”；
* 能给老板的方案自然铺垫。

## 优秀

* 每个负面判断都有截图或操作证据；
* 使用同一个标准任务对比平台；
* 区分事实、体验和推测；
* 把需求侧摩擦连接到供给侧收益；
* 不因 24 小时未接单就武断宣称平台没有需求；
* 最终导出 3～5 个产品要求；
* 汇报控制在 10～12 分钟；
* 能回答经理的追问：

> 为什么选这几个竞品？
> 共绩到底哪里不友好？
> RunPod 和共绩有什么本质不同？
> 这些开源工具能不能直接拿过来？
> 我们真正需要自研的是什么？
> 为什么用户会选择我们，而不是便宜的 GPU 云？
